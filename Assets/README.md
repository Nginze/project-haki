# Asset ownership

- **Engine/** owns reusable engine defaults: `Geometry`, `Materials`, `Shaders`, `Fonts`, `Skyboxes` and `Catalog.json`.
- **Game/Project.json** registers scene files and selects the entry scene.
- **Game/Shared/** owns intentionally reused game resources and its catalog. It is not an automatic dumping ground.
- **Game/Scenes/<scene>/** owns that scene's Blender source, scene JSON, catalog, import receipt, models,
  materials, textures, scripts and optional skyboxes. Empty type directories need not exist.

Open `Game/Scenes/arena-01/arena-01.blend` to author the current arena. Its generated
`arena-01.scene.json` explicitly names adjacent `Catalog.json`; the catalog imports Engine and Shared.
Asset source paths are relative to the catalog declaring them. IDs remain stable when files move.
A scene loads only its declared catalogs. The engine rejects duplicate IDs, hash collisions and import cycles.

## Authored versus generated

Blender files and Lua scripts are authored. Scene JSON, imported models/materials/textures, the local catalog's
imported entries, and `ImportReceipt.json` are generated by the pipeline. Receipts record generated files;
reimport preserves all other files and refuses to overwrite unowned output paths. Keep authored materials
under unique names/IDs; do not edit generated materials expecting edits to survive reimport.

Each scene's script paths start at its `Scripts/`. Reusable scripts start at `Game/Shared/Scripts/` and
are referenced as `shared/name.lua`; modules use `require("shared.lib.name")`. Local modules still use
`require("lib.name")`. Lua files are never loaded from the archive.

The Blender add-on's **Use Engine Default Skybox** explicitly enables the engine environment.
**Scene Skybox Asset** takes precedence and selects a texture ID from the composed catalog. Neither enabled
means no environment. Lighting, camera, physics, animation and scripting formats are otherwise unchanged.

## Import and run

```sh
.venv/bin/python tools/import_gltf_pack.py Assets/Game/Scenes/arena-01/Models/arena.glb \
  --pack arena-01 --scene arena-01 --set-entry --dry-run
cmake --build build -j2
./build/Engine
```

Remove `--dry-run` to import. Blender's Export Arena performs the same operation. Runtime packages keep
this directory layout but exclude `.blend` files, backups, receipts, hidden staging files and archives.
Only registered scene directories, Shared and Engine are packaged.

Original experiments are retained at `../Archive/Experiments/Assets`, outside runtime discovery and builds.
They are archival sources, not registered playable scenes. `tools/migrate_assets.py` documents the migration,
previews it by default, refuses archive collisions, and is a no-op once Game/Project.json exists.
