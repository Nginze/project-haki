# Arena 02

The visual target and current art shortcomings are recorded in [docs/artdirection.md](../../../../docs/artdirection.md), with colors in [docs/palette.json](../../../../docs/palette.json). This README describes the existing scene and export workflow, not visual approval.

`arena-02.blend` is the editable arena. `arena-02.scene.json`, `Catalog.json`, materials, textures and `Models/arena.glb` are generated by the Haki add-on's **Export Arena** operation. The source kit palette is preserved; the old yellow foliage modifier, visible spawn disks, duplicated lights and stacked outer wall ring have been removed.

## Layout and authoring

- The playable floor sits inside a 26 m canyon enclosure. A continuous sand mesh avoids tile grooves; four smaller ponds leave connected central routes.
- The four original L-shaped cover pockets remain, with spaced crates and concealment bushes. Short fence runs, two flowering barrel-cactus models and a few rocks dress the outer lanes.
- Canyon bounds use dedicated 4×2 m rim segments and 3×3 m corners. The foreground rim has a lower variant to avoid hiding the player.
- `Player` is an **Empty**, with Haki Character Controller, Local Player Input and `Scripts/player.lua`. It has no visible mesh or physical spawn platform. Attach a character visual later using the Haki Attached Visual workflow.
- Ground, boundaries, cover, crates, fences, large rocks and cacti have static box colliders. Four invisible pond volumes block water traversal. Bushes have nonblocking trigger volumes for future concealment logic; concealment gameplay is not implemented by this scene.

## Camera

The refinement recipe configures a **58° orthographic camera** with a **21.5 m authored view width at 16:9**. However, the current scene JSON reviewed on 19 November 2026 exports a **perspective camera with a vertical FOV of about 44.1°**. Resolve this source/export mismatch before using either profile to approve asset scale or terrain coverage.

`Scripts/arena_rules.lua` keeps the authored startup view until the moving player crosses the existing camera threshold. It pans smoothly and attempts a ground-framing clamp using runtime viewport aspect. The clamp's symmetric extent calculation needs checking against the actual perspective ground footprint; current coverage is not visually approved. The default engine skybox/IBL is enabled.

## Export and validation

Open the **Haki** sidebar and choose **Validate Arena**, then **Export Arena** with **Import into Haki** enabled. Project settings use `arena-02` for both Scene ID and Pack. This scene is the startup entry; project rendering/window/editor settings are preserved.

The prepared export contains 195 entities, one primary camera, one mesh-free controller, 127 solid colliders and 18 bush sensors. Import dry-run and final import pass. A 0.5 m grid check confirms the player starts outside blockers, all sampled walkable areas connect, and the sampled outer boundary is closed. This is a layout check, not a substitute for a full Jolt playtest.

Scene Lua passes syntax and LuaLS checks. Updated runtime assets are staged in `build/Assets`.

The scripted refinement is `tools/blender/arenas/refine_arena_02.py`; it modifies the scene in place. Read it before rerunning it against a newer authored scene. Its optional generated previews go to `output/previews/arena-02/`. The previous concept/preview/backup folder has been removed as part of the art-direction cleanup. Additional kit assets are generated by `tools/blender/kits/canyon_arena_assets.py`.
