# Canyon kit

Visual requirements are defined in [docs/artdirection.md](../../../../../docs/artdirection.md) and [docs/palette.json](../../../../../docs/palette.json). This README describes the current kit's technical contents; the existing assets are not yet a completed implementation of that direction.

These are modular pieces on a **1 m grid**. Each piece in `Models/` is its own `.glb`. The base kit shares a single material, `canyon_palette`, with one 64×64 palette texture to keep material changes low and support batching. The cactus additions use separate solid-color materials, as described below.

The meshes are generated by `tools/blender/kits/canyon_kit.py`; keep reusable changes in that script and rebuild (see the end of this file). `preview.png` shows a sample layout built only from these pieces; `details.png` shows the refined bush, stone, fence and water up close.

## Placement rules
- **Position:** place each piece at the centre of its cell (`x + 0.5, z + 0.5`). Its origin is at ground level.
- **Rotation:** rotate only in 90° steps.
- **Floor:** every walkable cell gets a floor piece: `sand_tile*` or `water_*`. Their tops sit at y = 0.
- **Water edges:** `water_edge` has its bank on the north side (−Z in the engine, +Y in Blender).
  - `water_corner_outer` has banks on the north and east sides.
  - `water_corner_inner` has a bank patch only in its north-east corner. Use it where a pond bends around a land corner.
  - Rotate these pieces to face other directions.
- **Fences:** put a `fence_post` on every fence cell. Between each pair of neighbouring posts, place a `fence_rail` on the first cell. The rail runs from that cell's centre to the next cell's centre along +X; rotate it for the other directions.

## Palette and refinement

Current colors are hard-coded in the generators and baked into the exported palette texture/materials. The canonical JSON records the target swatches; loading it into generation/runtime remains implementation work. Leaf, clay-side and wood swatches use height gradients. Swatches are written directly into an sRGB byte image; converting them to linear first would darken/saturate the exported PNG. Base-kit GLBs use a single `UVMap` / `TEXCOORD_0` with embedded palette data.

Stone layers are one continuous shell with 3.5 mm shallow grooves instead of separate deeply beveled stacks. The current bush has per-leaf variation within a one-metre footprint; further canopy/silhouette work is specified in the art direction. The preview studio sun is set to 2.6; it is not exported with the individual models and is not the gameplay lighting standard.

Water slabs and shoreline banks retain independent, outward-facing shells. The generator welds only within each part; welding and recalculating normals across the combined overlapping shells can invert the beige bank's top faces. `tools/tests/blender_canyon_water_smoke.py` checks the built geometry and actual GLB winding, normals and palette UVs for all three bank shapes.

## Arena boundary and cactus additions

`canyon_arena_assets.blend` contains an appendable `CanyonArenaAssets` collection and six marked assets. Their individual GLBs are in `Models/`:

| Piece | Footprint / use | Triangles |
| --- | --- | --- |
| `canyon_boundary` | 4×2 m broad canyon rim, 2.8 m main height | 218 |
| `canyon_boundary_low` | 4×2 m foreground rim, 1.2 m main height | 218 |
| `canyon_corner` | 3×3 m canyon corner, 3.15 m main height | 218 |
| `canyon_corner_low` | 3×3 m foreground corner, 1.35 m main height | 218 |
| `cactus_barrel`, `cactus_tall` | Two ribbed green barrel cacti with sparse cream thorns and pink flowers | 710 each |

Append the collection, or drag individual marked objects from a configured Blender asset library. Cacti share six small solid-color materials; the cliff additions use the original canyon palette. Model origins are at ground level. These pieces are produced by `tools/blender/kits/canyon_arena_assets.py` with `build_assets()`, `export_assets(objects)` and `write_library(objects)`.

## Rebuilding
1. Open `canyon_kit.blend`, or any Blender session, for example through Blender MCP.
2. Run:
   ```python
   ns = {}; exec(open("tools/blender/kits/canyon_kit.py").read(), ns)
   ns["build_all"](); ns["build_sample"](); ns["export_all"]()
   ns["render_preview"](); ns["render_details"]()
   ```
3. Save `canyon_kit.blend` after checking the assembled sample and individual pieces. Building updates linked sample meshes; call `build_sample` only when you want to rebuild the sample layout as well.
